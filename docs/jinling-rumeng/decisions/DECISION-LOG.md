# 《金陵入梦》设计决策日志

状态：ACTIVE
最后更新：2026-07-10
规则：已经确认的方向在此记录原因和影响。修改时新增决策，不悄悄改写历史。

## D-001：玩家不扮演任何原著角色

状态：ACCEPTED
日期：2026-07-10

决定：玩家创建原创人物，以自己的身份参与《红楼梦》主线。

原因：固定为原著人物或新写死的侍女会限制长期路线，也削弱玩家自我投射。

影响：废弃“玩家是阿绫/固定随行丫鬟”的方案；所有角色必须能直接承认和回应原创玩家。

## D-002：采用第一视角真人影游

状态：ACCEPTED
日期：2026-07-10

决定：正式剧情以玩家眼睛作为主机位，演员面向镜头与玩家交流。

原因：建立类似成熟第一视角 FMV 的直接情绪反馈，同时允许玩家保留自己的外貌投射。

影响：自由姓名不进入预录口播；玩家完整脸部不成为视频连续性依赖。

## D-003：原著锚点保留，玩家改变过程和余波

状态：ACCEPTED
日期：2026-07-10

决定：第一季保留黛玉进府、宝黛初见和宝玉摔玉等关键事件。

原因：玩家应参与经典主线，而不是以原创角色替换原著核心。

影响：交互不能无条件取消锚点；分支主要改变人物关系、局部结果和玩家命运。

## D-004：无字命册作为长期世界机制

状态：ACCEPTED
日期：2026-07-10

决定：用太虚幻境中的无字命册解释角色创建、存档、回放和玩家命运未被预写。

原因：把产品系统与红楼世界观统一，并为长期季节提供谜团。

影响：玩家创建、暂停、章节回顾、结局收藏和长期主悬疑共享同一命册语汇。

## D-005：Mock 不降低产品完整度

状态：ACCEPTED
日期：2026-07-10

决定：数据暂不入库，但角色创建、状态机、存档、章节回放、关系、结局和媒体错误处理全部真实工作。

原因：Mock 是数据适配器选择，不是临时产品标准。

影响：使用可替换 Repository，不把 Mock 常量散落在 UI。

## D-006：现有影游实现没有兼容义务

状态：ACCEPTED
日期：2026-07-10

决定：现有剧情、素材、播放器和生成脚本可以全部弃用。

原因：不让沉没成本限制最终产品。

影响：新引擎达到切换门槛后直接删除旧实现，不维护双运行时和静默回退层。

## D-007：技术形态服务叙事，不预设上限

状态：ACCEPTED
日期：2026-07-10

决定：按需要使用 Three.js、3D、360°全景、Tone.js、GSAP、HLS、Seedream 5、Seedance 2.0 和 SeedAudio。

原因：目标是完整沉浸影游，不以当前简单播放器为边界。

影响：运行时采用多 renderer 架构，同时要求懒加载、能力检测和可访问性替代方案。

## D-008：生成前先锁定内容与资产卡

状态：ACCEPTED
日期：2026-07-10

决定：没有 REVIEWED 场景卡和 LOCKED 人物、道具、分镜参考时，不批量调用生成服务。

原因：视频生成成本最高，剧情与连续性未锁定时反复生成会浪费成本并制造错误依赖。

影响：生成脚本未来必须读取机器可读 Asset Manifest，不继续硬编码少量场景。

## D-009：特殊按钮分离装饰与交互

状态：ACCEPTED
日期：2026-07-10

决定：Seedream 可生成纸、印、云锦等装饰纹理，但文字、命中区域、状态、焦点和本地化由 HTML/CSS 实现。

原因：位图按钮无法良好响应、本地化和支持无障碍。

影响：通用控制复用现有图标库，不生成整张带文字按钮图。

## D-010：生产验证章不是 Demo

状态：ACCEPTED
日期：2026-07-10

决定：批量生产前按最终标准完成并保留第一章，验证最终引擎和生产流水线。

原因：避免整季放大错误，同时不建立临时、需要推倒的 MVP 架构。

影响：验证章使用最终 ID、人物、素材、媒体和质量门槛，验收通过后直接进入正式内容。

## D-011：玩家是世界内原创人物，不采用现代穿越者口吻

状态：ACCEPTED
日期：2026-07-10

决定：玩家通过无字命册成为红楼世界内部真实存在的人物，不保留可用于破坏时代语境的现代身份和现代知识。

原因：更接近角色创建 RPG 的参与方式，避免现代吐槽和历史世界之间的长期冲突。

影响：所有出身、台词、道具和人物关系必须在红楼世界内部成立。

## D-012：保留三种出身，共用一个主线入口

状态：ACCEPTED
日期：2026-07-10

决定：保留江宁织造故人之后、贾府故交晚辈、金陵医馆学徒三种出身；共同作为贾母故交晚辈，持荐书入府。

原因：提供角色创建差异和重玩价值，同时避免三套完全独立视频主线造成内容爆炸。

影响：每种出身至少拥有两次专属方法和两次人物差异反应，主场景和原著锚点保持汇合。

## D-013：荐书是命册写入世界的真实凭证

状态：ACCEPTED
日期：2026-07-10

决定：荐书的旧署名、旧纸和旧交关系在世界内真实存在；异常是灯下可见、与无字命册相同的淡红纹印。

原因：同时满足合法入府、人物审查、3D 道具互动和长期悬疑，且能通过画面表现而非长篇考据解释。

影响：Seedream 道具标准、Seedance 特写、Three.js 材质和 SeedAudio 线索反馈必须统一表现这一纹印。

## D-014：选择“水墨实景”为主视觉方向

状态：ACCEPTED
日期：2026-07-10

决定：三套视觉探索中选择第一套“水墨实景”作为正式视觉基准。

原因：它最接近真人影游而非传统游戏菜单；无字命册自然成为交互物，秦淮水面与荣府建筑提供空间纵深，淡红纹印也能作为唯一强色长期使用。

影响：后续人物、道具、场景、UI 纹理和 Seedance 视频均需引用该基准。黑漆秘阁的材质可用于熙凤与夜间场景，纸页廊桥只作为太虚重大转场的辅助语汇。

## D-015：旧播放器已完成原子切换与素材清场

状态：ACCEPTED
日期：2026-07-11

决定：`/play/jinling` 直接切换到新无字命册入口；删除旧 9 段播放器、旧剧情/积分/结局、随机垫乐、硬编码生成脚本和全部未验收发布素材。

原因：旧入口把玩家写成黛玉的旁观者，且没有使用正式 Session、原创玩家 Profile、Reducer 或 PLAYER-POV 内核；继续换皮会保留错误的产品骨架。

影响：运行时不再提供旧视频回退。P00 使用最终版本化草稿和 Session 结构逐步扩展；SC01 以后只接入获得稳定 ID 并通过生产准入的正式资产。

## D-016：Seedream Pro 试制源与正式 4K 交付分层

状态：ACCEPTED
日期：2026-07-11

决定：P00 环境参考试制使用 Seedream 5 Pro 官方推荐的精确 2K 源尺寸（横版 2816×1584、竖版 1584×2816）；原始输出不可改写。为便于在目标画布评审，只允许按 manifest 明示的 Lanczos3、同画幅、无裁切方式派生 4K REVIEW 图。该派生只验构图、空间层次和灯光，不能晋级为正式 APPROVED 微纹理母版。

原因：Pro endpoint 实测拒绝 3840×2160 请求，且当前项目的 ModelArk 模型策略只开放 1K/2K。继续盲目重试会重复失败；把 Provider 源、评审派生和正式交付分开，才能保持来源真实性与晋级边界。

影响：生产 journal 同时记录 source/derived 的尺寸、格式和 SHA-256；正式 4K matte 必须在构图通过后另走支持 4K 的生成/超分生产步骤并重新验收，不能把评审放大图直接发布。

## D-017：Seedream 同步请求出现未知结果后禁止盲重提

状态：ACCEPTED
日期：2026-07-11

决定：`/images/generations` 采用 1800 秒总等待、0 次自动重试和 fingerprint 独占 journal。P00 横版、竖版已经提交而结果未确认的 fingerprint 永久停留 `UNKNOWN`，不以“客户端没拿到图片”为由重发。新的 Seedream 付费调用暂停，直到供应商能确认请求/计费状态，或另行评审并明确接受一次新的传输/区域验证成本。

原因：官方图片接口是同步调用，不返回可查询 task ID，也没有公开幂等键。P00 竖版在使用 `apps/web/.env.local` 凭据、正确 Pro endpoint、原生 HTTPS 和 1800 秒客户端 deadline 时，仍由远端在 62.725 秒关闭连接；这排除了本地 60 秒超时和错误凭据来源，但无法证明供应商端是否已经完成并计费。随后按控制台自动生成的 T2I 合同做了三条独立诊断：2K + HTTP/2 在 61.150 秒出现 framing error，1K + HTTP/2 在 61.717 秒出现相同错误，1K + HTTP/1.1 + 15 秒 TCP keepalive 在 61.294 秒收到空响应。固定边界与分辨率、提示词复杂度、HTTP 版本和 TCP keepalive 无关，后续必须更换执行节点或由 BytePlus 排查网关，不能继续在当前节点试参。

影响：journal 只记录脱敏的 `transportReason`、`elapsedMs`、`configuredTimeoutMs` 和可用 HTTP 状态，不记录 raw error、响应体、签名 URL 或凭据。当前本机不再发出 Seedream 请求；下一次探针只能在获授权的独立云端执行节点运行，或由用户在 ModelArk Console Trial 完成。Seedance 的异步任务 API不受此决定影响，但仍须等首末帧正式锁定后才能提交。

## D-018：正式素材生成复用 FizzDragon 云端任务系统

状态：ACCEPTED
日期：2026-07-11

决定：《金陵入梦》的正式 Seedream、Seedance 与后续生成任务通过现有 FizzDragon `/aurora/ai/jobs`、BullMQ Worker、Provider Adapter 和媒体归档链路执行；本机直连 ModelArk 只保留诊断证据，不再作为生产路径。

原因：FizzDragon 画布已用同一 Seedream 5 Pro 模型稳定产出；浏览器提交只创建异步平台 Job，真正的同步 ModelArk 图片请求由新加坡 Worker 持有。首个 P00 横版任务在云端稳定跨过本机约 61 秒断点并成功完成，证明模型、账号、请求映射和云端链路均正常。

影响：生产 runner 必须使用确定性 idempotency key、单任务提交、低频轮询、工作区隔离和本地脱敏 journal。临时授权的用户 session 只用于当前制作验证，不写入仓库或日志；最终自动化应改为服务身份。首个横版结果因中央月光倒影侵入命册安全区、左侧前景过重及秦淮开放感不足被标记为 `REVISION_REQUIRED`。V02 已修正为开阔水道、中远岸建筑、右侧月影和安静的下方中央交互区，评为 `REVIEW · DIRECTION_APPROVED`；它锁定构图和灯光方向，但仍不是可发布的最终 4K 环境母版。

## D-019：命册采用参数化 GLB 结构源并延后 DCC 微纹理精修

状态：SUPERSEDED BY D-020
日期：2026-07-11

决定：命册 V02 的第一份可运行结构资产由受控 JSON 参数和 Three.js `GLTFExporter` 确定性生成 GLB，不依赖本机不存在的 Blender。生成器、GLB 和验证器共同锁定米制尺寸、侧缝开启轴、节点、材质身份、七段动画名及 `LEDGER-IDLE` 1.5mm 位移上限；后续可导入 Blender 做纸纤维、布线、页角和动画曲线精修，但不得破坏合同。

原因：结构正确性、网页可加载性和可重复导出应先由机器合同保证，不能等待某一台工作站的 DCC 安装，也不能继续使用页面内临时盒体冒充资产。浏览器验收曾发现首版 GLB 同时显示闭合页堆与打开页，验证了“文件合法”不能代替画面复核；重构后左右页堆、封面与翻页叶已统一围绕侧缝轴。

影响：`S01-P00-B02-MODEL-LEDGER` 晋级 `REVIEW`，当前 GLB 已替换运行时临时几何并通过桌面与 390×844 竖屏加载。它仍不是最终 `APPROVED` 模型；PBR 微纹理和七段动画逐段视觉验收未完成前不得用于 Seedance 首帧或正式发布。

## D-020：影游改为视频主轨，P00 实时 GLB 方案废止

状态：ACCEPTED
日期：2026-07-11

决定：正式运行时以 Seedance 视频承载人物表演、运镜、环境变化和固定机位道具动作；HTML / Canvas 承载选择、字幕、自由姓名和印记。3D、全景与 PLAYER-POV 合成只作为玩家必须连续改变视角或操纵空间对象时的显式扩展。P00 命册出现、打开、等待、显墨、落印和转场改为 OPENING、WAIT/末帧保持、CONFIRM、TRANSITION 视频槽位，参数化 GLB 不再进入发布依赖。

原因：浏览器实机截图证明合法 GLB 与七段动画并不能产生真人影游质感，而且运行时实际只调用其中三段；为一个固定镜头建立 Three.js 水面、灯光、材质、相机和模型合同，会把创作者工作流错误地变成 DCC 工程。视频主轨既符合互动影游语法，也让未来创作者通过镜头、选择和分支生产内容，而不是编写 WebGL。

影响：

- `P00-PROD-CARD-V01` 标记 SUPERSEDED，V02 成为准源；
- Production Asset Manifest、Runtime Release、Creator Draft 分离；
- 运行时 Release 明确 MAIN / WAIT / REACTION / CONFIRM / TRANSITION / EXTENSION；
- 横竖版使用显式 `paired-required` / `single-master` 策略，禁止静默裁切；
- 玩家姓名和字幕禁止烧录进视频，必须使用受控绑定与安全区；
- GLB V01 只保留预演与审计价值，不再继续投入 PBR 和七段动画精修；
- Seedance REVIEW 任务通过完整媒体验收后才能替换页面，不以程序化几何或无关视频作回退。

## D-021：第一季对白 v1.0.0 锁定并固定横屏生产

状态：ACCEPTED
日期：2026-07-11

决定：`18-DIALOGUE-REVIEW.md` 与 `s01-dialogue-lock-v1.json` 共同成为第一季正式台词准源。玩家不使用固定配音，选择文本只表达回应意图；NPC 用分支反应台词承接。未知女声与纯画外音使用 SeedAudio，正面角色对白使用 Seedance 同步口型并保留可替换对白分轨。第一季所有正式对白镜头只生产 16:9 横屏，不再制作 9:16 成片。

原因：完整影游必须先锁定台词、分支条件、表演时长与声音策略，才能稳定生成口型视频。把一整场对白临时压成一句六秒台词只能验证流程，不能成为最终成片；同时维护横竖两套表演素材会使镜头连续性、成本和创作者合同无谓翻倍。

影响：现有十段六秒视频降级为人物身份、构图和动作参考。后续生产只能读取 LOCKED v1.0.0 机器合同；每句对白拥有稳定 `dialogueId`、独立 `shotId`、分支条件、目标时长、字幕与音频策略。手机端后续使用横屏提示，不触发竖屏素材生产。任何改词必须提升锁定版本并重新生成受影响的字幕、音频与视频指纹。

## D-022：P00＋SC01 成为首个可提交生产切片

状态：ACCEPTED
日期：2026-07-11

决定：以 `s01-p00-sc01-production-v1.json` 锁定首个端到端生产切片。P00 复用两条已验证的无声横屏视觉并外挂四条未知女声；SC01 拆为一条 12 秒主片和三条 6 秒选择反应片。车夫与未知女声使用独立 SeedAudio，黛玉正面台词使用经过画布上传确认、虚拟人像注册和状态等待的 Seedance 多模态同步口型路径。

影响：`s01-sc01-seedance-v1.json` 是四条 SC01 视频候选的唯一 runner 输入；旧 `s01-story-video-v01.json` 中与锁定台词不一致的六秒 SC01 片不得继续生产或覆盖运行时。所有新输出使用新路径和版本号，必须先进入 REVIEW，人工通过后才能晋级并接入正式 Release。

## D-023：首次流程压缩为约九分钟与四次显式选择

状态：ACCEPTED
日期：2026-07-11

决定：第一回内容目标约 9 分钟，常见实玩 9–11 分钟，硬上限 12 分钟；只保留入府、游廊护持、摔玉动作与荐书去向四次显式剧情选择。Seedance 单片仍受 15 秒上限约束，但运行时以 `presentation.sequence` 把多个镜头组成 45–140 秒的连续叙事段。

原因：原 18–22 分钟与 8–10 次选择会让第一回过长、剧情被频繁 UI 打断；历史六秒单片又把场景压成插入镜头，电影感和人物表演都不足。先建立完整长段观看节奏，再在关键不可替代的决定处交还控制权，才符合互动电影而非连续菜单。

影响：SC01 观察、SC05 回答、SC06 住宿、SC07 回应和 SC09 夜谈不再阻断播放，改由主片、历史状态变体或非阻断观察承载。播放器支持逐镜 `advance`、有限/无限末帧保持、静音尾段循环和独立 WAIT；对白与单向动作禁止来回循环。第一季正式媒体只生产 16:9 横屏，手机端提示横置。

## D-024：三分钟重构版玩家拥有固定画外主角声线

状态：ACCEPTED

决定：三分钟重构版中的玩家不露脸，但使用一套锁定的成年画外主角声线，并拥有完整、可被 NPC 听见和承接的台词。选择文本直接对应将要说出的台词或执行的动作；自由姓名仍不进入预录对白。
