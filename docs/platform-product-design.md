# FizzDragon 平台核心产品设计

状态：草案
负责人：FizzDragon Platform
关联技术文档：`docs/platform-product-technical-design.md`

## 1. 产品目标

FizzDragon 要从一组 AI 创作功能，升级为一个完整的创作协作和创作者商业平台。

目标不是先上线一个低配 MVP，而是完整设计平台核心能力，开发分阶段推进，等核心闭环达到产品级后再上线。

平台需要让用户完成这些事情：

- 创建项目
- 使用 StoryOS 创作故事、角色、场景、分镜
- 使用图片、视频、音乐、语音等 AI 工具生成资产
- 多人协作修改分镜、剧本、时间线和画布
- 管理项目资产、个人资产和团队资产
- 使用个人或团队额度进行生成
- 购买课程、IP、剧集和创作者服务
- 发布服务包、接单、沟通、交付、结算
- 在后台可追踪成本、收入、失败、退款和异常

一句话：

> FizzDragon 是面向 AI 动画和 IP 创作的项目协作系统、AI 生产系统和创作者商业系统。

## 2. 产品定位

FizzDragon 不是单纯的 AI 生图工具，也不是单纯的内容社区。

它应该同时具备三层能力：

### 2.1 创作工具层

用户可以完成：

- StoryOS 对话创作
- 分镜表编辑
- 图片生成
- 视频生成
- 音乐生成
- 语音生成
- 改图 / 改视频
- 时间线剪辑
- 画布整理

### 2.2 项目协作层

用户可以围绕一个项目协作：

- 邀请成员
- 分配任务
- 共享项目资产
- 同时编辑分镜
- 围绕镜头、角色、场景讨论
- 将 AI 建议应用到项目
- 管理项目容量和资产权限

### 2.3 创作者商业层

平台可以支持交易：

- IP / 剧集购买
- 课程购买
- 创作者服务包
- 订单沟通
- 交付验收
- 社区积分
- 创作者收入
- 会员权益
- 团队套餐

## 3. 用户角色

### 3.1 普通创作者

目标：

- 创建自己的 AI 动画 / IP 项目
- 使用 AI 工具降低创作成本
- 管理个人项目和个人资产
- 逐步积累作品和个人主页

核心需求：

- 快速开始创作
- 生成图片、视频、音乐
- 有清楚的额度和成本提示
- 可以邀请少量协作者
- 不担心资产丢失或权限混乱

### 3.2 项目 Owner

目标：

- 组织一个完整项目
- 管理成员、资产、分镜、时间线和交付
- 控制项目成本和存储

核心需求：

- 项目资产归属清楚
- 成员权限清楚
- 可以查看生成历史和成本
- 可以转移项目
- 可以保护项目内资产和历史版本

### 3.3 协作者

目标：

- 加入别人的项目进行创作
- 在项目内使用 StoryOS 和 AI 工具
- 提交自己的创作成果

核心需求：

- 知道自己生成的资产归谁
- 知道消耗谁的额度
- 离开项目后规则清楚
- 可以保留个人生成记录

### 3.4 团队 / 工作室

目标：

- 用团队空间管理多个项目
- 统一成员、资产、预算、审计和权限
- 支持商业交付

核心需求：

- 团队额度池
- 团队资产库
- 成员和席位管理
- 项目预算
- 审计日志
- 成本和收益报表

### 3.5 内容消费者

目标：

- 购买课程、IP、剧集
- 学习并进入创作
- 使用社区积分参与平台内容

核心需求：

- 价格清楚
- 权益清楚
- 购买后可访问
- 试看和购买路径清楚

### 3.6 创作者服务买家

目标：

- 找到创作者
- 购买服务包
- 填写需求
- 沟通交付
- 验收成果

核心需求：

- 服务范围清楚
- 报价清楚
- 工期清楚
- 沟通和交付在一个订单里闭环

### 3.7 运营 / 管理员

目标：

- 处理异常
- 查看收入、成本、失败率、退款
- 管理模型、队列、会员、权益、订单

核心需求：

- 可查
- 可修
- 可退款
- 可重试
- 可审计

## 4. 核心产品对象

### 4.1 Workspace

Workspace 是用户或团队的账户空间。

用户看到的是：

- 个人空间
- 团队空间

Workspace 决定：

- 存储容量
- 会员 / 团队套餐
- 钱包和积分
- 项目归属
- 权限和审计范围

### 4.2 Project

Project 是所有创作发生的地方。

项目里包含：

- StoryOS
- 分镜表
- 时间线
- 画布
- 剧本
- 项目资产
- 项目成员
- AI 生成任务
- 项目聊天和协作记录

用户应该感知：

> 我正在某个项目里创作，这里的资产和结果默认属于这个项目。

### 4.3 Asset

资产包括图片、视频、音乐、语音、文件、缩略图、生成结果。

产品规则：

- 项目里生成的资产归项目。
- 项目里上传的资产归项目。
- 从个人图库加入项目时，需要明确变成项目资产或授权给项目。
- 项目资产不自动进入个人图库。
- 用户可以在允许时保存个人副本。
- 被项目引用的资产不能被物理删除。

### 4.4 Document

Document 是项目里的创作工作区，不是用户文案。

用户看到的是：

- 分镜表
- 时间线
- 画布
- 剧本
- StoryOS 会话

产品规则：

- 不同工作区共享同一份核心内容。
- 分镜表负责叙事规划。
- 时间线负责播放和剪辑编排。
- 画布负责空间组织和关系整理。
- StoryOS 负责对话、推理和生成建议。

### 4.5 Proposal

Proposal 是 AI 或批量操作提出的待确认修改。

产品规则：

- AI 不能直接改正式内容。
- 用户必须先看到变更预览。
- 用户确认后才应用到项目。
- 应用后写入历史和审计。

## 5. 核心产品规则

### 5.1 资产归属规则

在 project 上下文中：

| 行为                 | 资产归属             |
| -------------------- | -------------------- |
| 在项目里生成图片     | 项目                 |
| 在项目里生成视频     | 项目                 |
| 在项目里生成音乐     | 项目                 |
| 在项目里上传本地文件 | 项目                 |
| 从个人图库加入项目   | 项目副本 / 项目授权  |
| 项目资产保存个人副本 | 个人，前提是权限允许 |

即使操作者是 owner，只要是在项目里产生，也默认归项目。

### 5.2 存储容量规则

容量属于 workspace，不属于 project。

项目只是占用 workspace 容量：

```text
个人空间
  - 项目 A
  - 项目 B
  - 个人图库

团队空间
  - 团队项目 X
  - 团队项目 Y
  - 团队资产库
```

项目可以有项目级用量上限，但不是独立购买容量的账户。

### 5.3 项目转移规则

项目转移是把项目从一个 workspace 转到另一个 workspace。

完整项目转移包含：

- 项目资产
- 分镜表
- 时间线
- 画布
- 剧本
- StoryOS 会话
- 生成记录
- 项目成员记录
- 历史版本

接收方 workspace 必须有足够容量。

历史费用和历史审计不重新归账。

### 5.4 协作者退出规则

协作者退出项目后：

- 不能继续访问项目资产。
- 不能下载项目原始文件。
- 不能查看项目聊天和正式内容。
- 个人生成历史可保留。
- 历史里是否显示缩略图，由项目策略决定。

### 5.5 个人项目和团队项目区别

个人项目：

- 属于 personal workspace。
- 支持轻协作。
- 额度和容量来自个人会员。
- 权限简单。

团队项目：

- 属于 team workspace。
- 支持团队成员、席位、预算、审计。
- 额度和容量来自团队套餐。
- 适合商业项目和组织协作。

## 6. StoryOS 产品设计

### 6.1 多会话

一个项目可以有多个 StoryOS 会话：

- 项目主会话
- 我的工作会话
- 角色会话
- 场景会话
- 镜头会话
- 时间线片段会话

多人可以同时使用 StoryOS，不应该共用一个混乱的聊天窗口。

### 6.2 会话可见性

会话类型：

| 类型         | 可见范围     | 用途                            |
| ------------ | ------------ | ------------------------------- |
| 项目主会话   | 项目成员     | 项目级讨论和决策                |
| 我的工作会话 | 默认仅本人   | 个人探索和草稿                  |
| 对象级会话   | 根据对象权限 | 围绕角色、场景、镜头、clip 讨论 |

团队项目可以增加设置：是否允许管理员查看个人工作会话。

### 6.3 AI 输出应用

StoryOS 输出后，用户可以：

- 应用到项目
- 保存草稿
- 生成资产
- 分享到项目主会话
- 拒绝

应用前必须展示：

- 改了什么
- 影响哪个对象
- 是否覆盖已有内容
- 是否和别人修改冲突

## 7. 分镜表产品设计

### 7.1 分镜表定位

分镜表是叙事和镜头规划，不是时间线。

它用于管理：

- 镜头顺序
- 镜头号
- 画面描述
- 台词
- 场景
- 角色
- 景别
- 镜头运动
- 计划时长
- 状态
- 参考图
- 生成图 / 视频
- 音乐 / 音效
- 提示词
- 负责人
- 备注

### 7.2 实时协作

分镜表要支持类似飞书表格的体验：

- 多人同时编辑
- 单元格级保存
- 在线成员提示
- 冲突提醒
- 撤销 / 重做基础
- 历史版本
- 变更记录

### 7.3 AI 修改分镜

AI 可以建议：

- 新增镜头
- 删除镜头
- 拆分镜头
- 合并镜头
- 批量调整风格
- 批量补充提示词
- 批量生成画面描述
- 批量调整计划时长

但所有修改必须先进入 proposal，不能直接改正式分镜。

## 8. 时间线产品设计

### 8.1 时间线定位

时间线是剪辑编排，不是分镜表。

时间线负责：

- 多轨道
- clip 起止时间
- clip 重叠
- 音频和视频层级
- 转场
- 字幕
- 特效
- 调整层
- AI 编辑结果

### 8.2 分镜和时间线关系

分镜顺序是叙事规划。

时间线顺序是实际播放和剪辑编排。

规则：

- 在时间线移动 clip，不自动改变分镜表顺序。
- 修改时间线 clip 时长，不自动改变分镜计划时长。
- 如果要同步回分镜表，必须让用户确认。

UI 应提示：

> 时间线与分镜计划不一致。

并提供：

- 仅保留时间线调整
- 同步实际时长到分镜
- 根据时间线生成分镜调整 proposal

## 9. 画布产品设计

### 9.1 画布定位

画布是空间化整理视图。

用于：

- 整理角色关系
- 摆放场景和参考图
- 组织分镜卡片
- 管理生成变体
- 可视化故事结构
- 和 StoryOS 一起做创作推理

### 9.2 画布规则

画布节点引用项目内容，不复制内容。

例如：

- 节点可以引用某个 shot。
- 节点可以引用某个角色。
- 节点可以引用某个资产。
- 节点可以引用某个场景。

用户在画布中改内容时，也应该走 proposal 或明确保存动作。

## 10. AI 生成产品设计

### 10.1 统一入口规则

所有 AI 生成入口都要给用户讲清楚：

- 生成到哪里
- 消耗谁的额度
- 预计消耗多少积分
- 当前是否排队
- 失败是否退款
- 是否可以选择模型
- 生成结果是否属于项目

### 10.2 任务状态

用户应该看到清楚状态：

- 等待中
- 排队中
- 生成中
- 上传中
- 成功
- 部分成功
- 失败
- 已退款

### 10.3 错误反馈

错误不能只显示“生成失败”。

应该显示：

```text
生成失败：供应商返回参数错误。
原因：当前模型不支持空歌词生成纯音乐。
本次未扣费，冻结积分已退回。
```

### 10.4 多结果

有些模型一次返回多个结果，例如音乐一次返回两首。

产品上应该展示为：

```text
一个生成任务
  -> 结果 A
  -> 结果 B
```

不能把用户误导成两次独立任务。

## 11. 积分和会员产品设计

### 11.1 工具积分

工具积分用于 AI 工具算力：

- 生图
- 生视频
- 生音乐
- 生语音
- 改图
- 改视频
- Agent 调用
- 队列加速

### 11.2 社区积分

社区积分用于社区和内容交易：

- 课程购买
- IP 解锁
- 剧集购买
- 创作者服务包
- 活动奖励
- 社区折扣

### 11.3 会员

会员不是余额，而是权益包。

会员可以包含：

- 每月工具积分
- 每日免费额度
- 队列优先级
- 并发提升
- 高级模型
- 存储容量
- 社区积分倍率
- 折扣
- 协作者数量

### 11.4 团队套餐

团队套餐提供组织能力：

- 团队席位
- 团队额度池
- 团队存储
- 团队资产库
- 项目预算
- 审计日志
- 成员离职资产保留

## 12. IP 和剧集产品设计

### 12.1 IP 基础内容

IP 包含：

- 标题
- 封面
- 简介
- 剧集
- 作者 / 版权信息
- 展示状态

这些可以短期来自 legacy Java。

### 12.2 IP 商业化

商业化由新系统负责：

- IP 价格
- 剧集价格
- 免费试看
- 购买权益
- 会员折扣
- 社区积分支付
- 退款规则
- 创作者收入
- 购买后访问权限

### 12.3 剧集购买

购买前用户必须看到：

- 剧集名称
- 价格
- 当前余额
- 是否有折扣
- 购买后解锁范围
- 是否支持退款

购买后：

- 立即获得访问权益。
- 余额和流水可查。
- 权益在个人或团队范围内明确。

## 13. 课程产品设计

课程是体系化商品，不是散视频。

课程结构：

```text
Course
  Chapter
    Lesson
```

课程需要支持：

- 课程广场
- 课程详情
- 章节和课时
- 免费试看
- 整课购买
- 学习进度
- 购买权益
- 后台管理
- 上下架

课程优先用社区积分购买。

## 14. 创作者服务产品设计

创作者服务不是展示卡片，而是交易入口。

完整闭环：

```text
创作者发布服务包
  -> 买家查看服务
  -> 买家填写 brief
  -> 创作者确认范围 / 报价 / 工期
  -> 订单开始
  -> 站内沟通
  -> 交付
  -> 修改 / 验收
  -> 完成结算
  -> 评价和收入统计
```

服务包需要包含：

- 标题
- 交付内容
- 价格
- 工期
- 修改次数
- 需求表单
- 作品案例
- 上架状态

## 15. 后台产品设计

后台不是附加功能，而是生产级必需品。

后台需要支持：

- 用户查询
- 钱包和积分流水查询
- 人工调整
- 生成任务查询
- 失败原因查看
- 任务重试 / 取消 / 退款
- 模型配置
- 供应商健康度
- 队列状态
- 成本和毛利
- 存储占用
- 资产保留状态
- IP / 课程 / 订单权益查询
- 会员状态查询
- 团队状态查询
- 审计日志
- 告警记录

没有后台就无法支撑真实运营。

## 16. UI / UX 总要求

### 16.1 用户必须知道当前上下文

任何创作界面都要清楚显示：

- 当前项目
- 当前 workspace
- 当前资产归属
- 当前额度来源

### 16.2 用户必须知道成本

生成或购买前必须展示：

- 预计消耗
- 余额
- 折扣
- 失败退款规则

### 16.3 用户必须知道结果保存在哪里

生成前应提示：

```text
生成结果将保存到当前项目资产库。
```

或：

```text
生成结果将保存到你的个人图库。
```

### 16.4 错误必须可操作

错误要告诉用户：

- 失败原因
- 是否扣费
- 是否退款
- 能否重试
- 怎么解决

## 17. Java 和新系统产品边界

Java 可以继续负责：

- 老用户资料
- 老 IP 基础内容
- 老项目 / 剧集基础资料
- 老素材记录
- 老接口维护
- 老数据迁移支持

Java 不应负责：

- 新积分
- 新会员
- 新团队
- 新订单
- 新购买
- 新权益
- 新协同分镜
- 新时间线
- 新 AI 队列

## 19. 上线验收标准

上线前必须满足：

- 用户知道资产归属。
- 用户知道额度来源。
- 用户知道生成成本。
- 失败任务不会错误扣费。
- 退款可追踪。
- 项目转移有容量检查。
- 协作者退出权限正确。
- 被引用资产不会丢。
- StoryOS 修改要确认。
- 分镜表可多人编辑。
- 时间线和分镜关系清楚。
- 购买后权益立即生效。
- 后台能查、能修、能退款。
- 线上异常能告警。
