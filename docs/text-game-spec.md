# 文游产品需求

## 一句话

创作者上传一份世界观文档（docx），配上海报、角色、剧照和背景音乐，发布成一个作品；玩家进来点「开始游戏」，之后所有对话都由 LLM 基于这份文档展开。

分工：**创作者端和玩家端都由 Java 负责**。

---

## 创作者端

创建一个文游作品，需要填这些内容：

| 内容       | 说明                                           | 必填 |
| ---------- | ---------------------------------------------- | ---- |
| 名称       | 作品名                                         | 是   |
| 海报       | 列表和详情页的主视觉（不用文件夹列表那种形式） | 是   |
| 简介       | 一段话介绍                                     | 是   |
| 世界观文档 | 上传 docx，这是游戏的全部设定来源              | 是   |
| 角色       | 从平台已有的 AI 角色里挑选，可多选             | 否   |
| 剧照       | 上传多张图，游戏中展示                         | 否   |
| 背景音乐   | 上传音频，游戏中循环播放                       | 否   |

---

## 发布

作品有四种状态：

| 状态   | 含义                         | 玩家能不能看到 |
| ------ | ---------------------------- | -------------- |
| 草稿   | 创作中，随便改               | 看不到         |
| 审核中 | 已提交，等平台审核           | 看不到         |
| 已发布 | 审核通过，正式上线           | 能看到、能玩   |
| 已下架 | 创作者主动下架，或被平台下架 | 看不到         |

规则：

- **必填项齐了才能提交发布**：名称、海报、简介、世界观文档；
- **审核**：文档正文、海报、剧照、简介都要过审。审核不通过要给出原因，创作者改完可以再提交；
- **发布后修改不影响线上**：已发布的作品再编辑，改的是草稿，玩家看到的仍是线上那一版，直到重新提交并审核通过才替换；
- **下架**：创作者可以随时下架；平台也可以强制下架（比如举报处理）。下架后列表和详情都不再出现；
- **已经在玩的玩家**：作品下架或更新时，正在进行的对话不中断，让他把这一局玩完；下次进来才按新状态处理。

---

## 玩家端

三个页面：

1. **列表页**：卡片流，展示海报 + 名称 + 简介。
2. **详情页**：海报、名称、简介、**角色表**（参考豆瓣电影的演员表：头像 + 角色名 + 一句话介绍）、开始游戏按钮。
3. **游戏页**：对话式界面。进来先自动生成开场，之后玩家自由输入、LLM 回复，一直玩下去。
   - 背景音乐循环播放，玩家可以关；
   - 剧照在合适的时候展示（v1 简单轮播即可）；
   - 对话记录要保存，玩家退出后再进来能接着玩。

---

## LLM 怎么用这份文档

每次对话都要把世界观文档的内容带上，让 LLM 严格按文档里的设定来演。角色如果选了，也要把角色的人设一起带上，保证 NPC 说话符合人设。

文档一般几千字，可以整份放进上下文，不需要做切片检索。

---

## 需要平台侧（我们）提供的

- **AI 角色数据**：角色列表、头像、人设文本——创作者端挑选、玩家端展示、LLM 上下文都要用；
- **文件上传**：海报、剧照、背景音乐、docx 走现有的媒体上传和审核流程；
- **docx 解析**：如果 Java 侧不方便处理，我们可以提供把 docx 转成纯文本的接口。

---

## v1 不做

- 不做自定义角色（只能从平台已有的 AI 角色里选）；
- 不做剧情节点绑定（剧照和音乐都是全局的，不跟剧情走）；
- 不做多结局、存档分支这些复杂机制——就是一条对话线玩到底；
- 不做玩家自己上传文档来玩（只有创作者能建作品）。
