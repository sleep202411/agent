# FizzDragon 功能修复与发布记录

状态：内部持续维护

## 1. 说明

本文用于记录 FizzDragon 线上问题、功能修复、配置变更、部署修复和验证结果。

每条记录需要明确：

- 发生了什么问题。
- 影响哪个模块和环境。
- 当前处理状态。
- 责任人是谁。
- 谁实际修复。
- 谁负责验证。
- 是否已经部署。
- 是否还有后续事项。

后续新的线上问题、功能修复和部署记录，可以继续追加到同一个台账中。

## 2. 推荐飞书结构

建议在飞书中使用：

```text
Wiki 页面：FizzDragon 功能修复与发布记录
多维表格：功能修复台账
```

页面顶部保留本文的说明、状态定义、优先级定义和维护规则。

页面主体嵌入多维表格，用于长期维护所有修复记录。

## 4. 推荐视图

| 视图名             | 用途                                      |
| ------------------ | ----------------------------------------- |
| 全部记录           | 所有问题和修复记录，按日期倒序            |

| 已部署待验证       | 已上线但还没有最终确认                    |

| 按模块             | 按 StoryOS、AI 生成、上传、支付等模块分组 |
| P0/P1 高优先级     | 只看高优先级问题                          |

## 5. 状态定义

| 状态   | 含义                                 |
| ------ | ------------------------------------ |
| 待处理 | 已记录，尚未开始处理                 |
| 修复中 | 已开始定位或开发                     |
| 待部署 | 代码或配置已完成，等待部署           |
| 已部署 | 已部署到目标环境，等待验证           |
| 已验证 | 已确认线上或目标环境正常             |
| 挂起   | 依赖第三方、权限、产品决策或外部资源 |
| 关闭   | 不需要继续处理，或已被其他记录覆盖   |

## 6. 优先级定义

| 优先级 | 说明                                     | 响应建议 |
| ------ | ---------------------------------------- | -------- |
| P0     | 核心功能不可用、生产服务中断、支付不可用 | 立即处理 |
| P1     | 重要功能异常，影响主要用户流程           | 当天处理 |
| P2     | 局部体验问题或非核心功能异常             | 排期处理 |
| P3     | 文案、样式、小优化                       | 有空处理 |

## 7. 维护规则

1. 所有线上问题、功能修复、配置变更、部署修复都需要登记。
2. 每条记录必须有责任人。
3. 如果已经修复，需要补充修复人。
4. 如果已经上线，需要补充部署环境和部署时间。
5. 如果已经验证，需要补充验证人和验证结果。
6. 如果发现遗留问题，不要塞进原记录里，单独新增一条。
7. Commit / PR / 日志 / 截图等证据尽量挂到记录里。
