### 8.3 Q2：AI 生图 / 生视频失败率较高

| 字段     | 内容                |
| -------- | ------------------- |
| 模块     | AI 生成             |
| 类型     | 线上问题 / 系统优化 |
| 优先级   | P0                  |
| 影响环境 | 生产环境            |
| 当前状态 | 修复中              |
| 责任人   | Isaac               |
| 修复人   | 待补充              |
| 验证人   | 待补充              |

问题现象：

- 用户在生图、生视频过程中出现失败、等待时间长、接口超时等问题。
- 高峰期更容易出现失败。
- 用户无法清楚知道失败原因，也难以判断是否需要重试。

原因摘要：

1. 供应商侧存在调用频率和并发限制。
2. 任务缺少统一排队和调度，容易出现资源抢占。
3. 不同模型对图片尺寸、比例、时长、参考图等参数要求不同，当前校验不够前置。
4. 生视频任务耗时较长，直接等待接口返回容易超时。

已处理：

- 已初步确认问题不只是单个接口异常，而是任务调度、供应商能力和参数校验共同导致。
- 已开始梳理模型配置、任务队列、错误反馈和失败处理规则。

后续动作：

- 建立统一 AI 任务队列，明确排队中、生成中、成功、失败、取消等状态。
- 梳理模型参数规范，让前端提交前就能提示不合法参数。
- 后端保留最终参数校验，避免无效请求进入供应商。
- 对生视频等长任务使用异步任务和状态轮询。
- 失败时展示明确原因，例如参数错误、供应商限流、任务超时、系统异常等。
- 补充失败重试和补偿规则，避免用户只看到“失败”而不知道下一步怎么做。

## 9. 共性问题总结

本次反馈反映出的共性问题：

1. 高并发和推广场景下，AI 生成能力需要更强的排队、调度和错误反馈。
2. 大文件上传和静态资源流量不应长期压在业务服务器上。
3. 支付、订单、上传、AI 任务等关键链路需要后台可观测能力。
4. 用户数据相关问题必须有操作留痕，否则排查成本过高。
5. 所有线上问题需要统一记录状态、责任人、修复人和验证结果。

## 10. 近期建议

短期优先级：

1. **AI 任务队列和错误反馈**
   - 优先解决生图、生视频失败率、超时和用户无感等待问题。

2. **上传链路优化**
   - 上传直连对象存储，降低业务服务器压力。

3. **线上监控和告警**
   - 建立账户资源、模型调用、接口耗时、服务器负载、上传失败率等监控。

4. **支付问题排查能力**
   - 后台能查看订单状态、失败原因和人工处理记录。

5. **操作留痕**
   - 对关键业务数据增加操作记录，提升数据问题排查效率。
