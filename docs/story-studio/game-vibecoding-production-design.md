# FizzDragon 影游自定义与对话编程设计

当前产品边界：创作者在已有影游项目内，通过官方 Harness 对话修改作品界面。视频、章节、剧情分支、选项、数值与存档继续由影游运行时拥有。源码能力增强这个项目，不建立另一套游戏运行时。

已实现项目试玩页面、左右窗口隔离、共享播放器、统一 CSS/SVG 主题、自定义菜单源码、编译检查与项目版本保存。项目授权的官方对话入口、HTTP/WebSocket 代理和持久工作区已部署到 `.com` 新加坡 ACK。部署和就绪检查不代表全部产品流程已验收；具体范围见第 9 节。当前源码 SDK 可调用真实的开始、继续、重新开始、地图和返回菜单；任意游玩界面、素材 API 与数值读写仍未提供。

## 1 产品归属与用户流程

影游项目是唯一创作实体，沿用项目身份、权限、章节、草稿、制作素材与发布版本。创作者从项目进入试玩页面，左侧运行真实影游，右侧使用官方 Harness 对话。保存后返回同一项目；原制作画布和章节流程继续成立。

作品可以有固定背景的主菜单，开始与情节地图入口可以按源码自由排列。点击开始进入原影游；返回菜单暂停同一局，继续保留原有媒体位置、剧情状态和路线。菜单可自定义，剧情动作仍执行现有访问检查。

用户流程：打开项目 → 进入试玩 → 描述修改 → Harness 编辑并检查 → 左侧试玩 → 保存到项目 → 使用现有 Build / 发布流程。

“候选源码”“可运行预览”“已保存项目”“已发布版本”分别表示不同状态。编译失败时保留候选文件和最后可运行版本；项目保存使用版本比较，冲突不能覆盖另一份修改。发布继续沿用现有权限与确认。

## 2 现有职责

| 层         | 当前职责                                                       |
| ---------- | -------------------------------------------------------------- |
| Studio     | 项目试玩页面、可调整的左右面板、浏览器草稿、预览提案与保存反馈 |
| Game Agent | 官方 Harness 会话、模型调用、原生外观工具与菜单源码工具        |
| Server     | 项目授权、源码重新编译、版本比较、项目保存与 Build             |
| 共享播放器 | 视频、时钟、交互、地图、访问控制、暂停与检查点                 |
| Game SDK   | 向自定义菜单暴露同一播放器的有限动作和只读可用性               |

`apps/game-agent` 是独立服务。Harness 自己负责对话与工具循环，不引入 Agent OS 的 LangGraph、journal、Ably、协议或配置。模型使用独立的 `GAME_AGENT_*` 配置，凭据留在服务端；必须配置的值缺失时启动失败。

单次设计请求与官方聊天窗口共用 `appearance-harness-plugin`，外观读取、校验、合并与提交只保留一份实现。服务端入口固定工具权限：单次请求只开放三个外观工具，聊天窗口增加影游菜单文件工具；用户请求和模型不能改变权限。外观与菜单源码提交共用请求版本检查、重复提交拦截与原子结果写入，失败写入可重试。

Web 与 Studio 共同使用 `packages/experience-player-react`。两端适配器处理各自的账号、访问和保存职责；播放器与自定义菜单实现共享。试玩和正式 Build 使用同一菜单产物契约。

## 3 界面能力与实现状态

| 能力                                 | 当前实现                                                                  |
| ------------------------------------ | ------------------------------------------------------------------------- |
| 原生开始、播放条、选项、暂停的样式   | 唯一受校验的 CSS/SVG 主题；区域根节点提供安全对齐，部件规则提供布局与外观 |
| 默认开始文案和自定义文案             | 三种语言的开始按钮文案配置，默认使用平台翻译                              |
| 自定义主菜单布局                     | JavaScript / TypeScript、CSS、JSON、SVG 源码，入口导出 `mount`            |
| 开始、继续、重开、地图、返回菜单     | 调用真实宿主动作，重新检查当前可用性                                      |
| 完整自绘情节地图                     | 尚未提供节点和路线数据 API；当前打开真实宿主地图                          |
| 任意播放界面、选项界面和暂停界面源码 | 尚未提供相应源码挂载与动作接口                                            |
| 源码读取和修改影游数值               | 尚未提供受控状态接口；原引擎仍负责条件和效果                              |
| 使用项目素材                         | 菜单支持宿主提供的封面；通用授权素材 API 尚未提供                         |

外观契约仅保留 `{version:1,presentation:{theme?,copy?}}`。CSS/SVG 主题是唯一视觉来源，文案独立保存；旧皮肤和区域参数不再进入播放器、工具或新保存接口。已有数据库外观和浏览器草稿在读取入口显式转换为同一主题，保留原 CSS 优先级、素材和文案；转换失败明确报错，不清空原数据。自定义菜单源码仍是独立的隔离挂载能力，不与原生样式叠加。

工作台由项目范围的 Zustand 管理当前草稿、输入草稿、项目基准版本与撤销检查点；官方 Harness 保管对话。删除候选标签、闲置历史列表与重复聊天消息。持久化格式 v2 在原项目键中按源码/产物哈希引用同一版本，最多保留 40 个撤销检查点，并按 2 MiB UTF-16 存储预算裁剪最旧记录。当前草稿不因预算裁剪而丢弃；实际配额失败时内存仍保留修改并显示保存失败，既有磁盘草稿不被覆盖。构建语义版本升至 9，避免复用旧外观契约产物。

媒体默认完整显示作者画幅。菜单封面使用 `object-fit: contain`；源码响应式布局按左侧窗口尺寸适配，保持真实按钮、键盘焦点、触摸目标和减少动态效果支持。

## 4 SDK 的当前契约

`GameSession` 提供 `getSnapshot()`、`subscribe(listener)` 和 `invoke(action)`。快照只包含菜单／游玩界面、会话状态、地图状态和动作可用性；没有可直接修改的 controller、剧情变量或内部对象。

| 动作          | 宿主行为                                 |
| ------------- | ---------------------------------------- |
| `start`       | 通过现有准备与访问流程开始影游           |
| `continue`    | 离开菜单，继续同一局和媒体位置           |
| `restart`     | 结局后明确重新开始，撤销旧会话           |
| `open-map`    | 打开真实情节地图，开始前不提前进入剧情   |
| `close-map`   | 关闭地图并恢复对应界面与焦点             |
| `return-menu` | 暂停已挂载的影游并显示主菜单，不重置数值 |

动作执行时再次检查访问与运行状态，阻止重入和已失效会话。可信组件直接调用 SDK；生成菜单通过 MessageChannel 使用同一份会话。命令失败必须展示真实结果，不能伪造成功。

后续增加播放、选项、地图数据、玩法结果或数值接口时，扩展同一影游运行时和 SDK。读取返回不可变视图；写入经现有 controller 检查活动实例、声明能力、参数和访问规则。生成代码不直接读写内部状态。

## 5 数值与存档归属

保留 `packages/shared/src/story-stats.ts` 的作者数值语法，以及现有 Runtime Manifest 状态定义、条件、效果与检查点。

数值编辑器是创作表示，影游引擎是执行权威。对话编程接入这份状态，不能另建同名变量并使剧情条件和代码 HUD 使用不同数据。作品级／跨章节状态如需扩展，应有明确版本和迁移规则；不能静默改变已有 session 或已发布作品的含义。

正式玩家存档继续走 Web 的现有保存路径；Studio 继续走现有试玩行为。Game SDK 当前没有新增数值存储或独立浏览器存档模块。

## 6 源码与构建

当前源码契约只接受 `apiVersion: 1`、`surface: "main-menu"`。虚拟文件只支持 JavaScript、TypeScript、CSS、JSON、SVG；入口必须导出 `mount({root,game,context})` 并返回清理函数或相应 Promise。

文件数量上限 24，总源码上限 256 KiB，构建产物上限 768 KiB。只解析工程内精确相对引用，不安装包，不加载远程依赖或用户构建脚本，不执行用户代码。固定 esbuild 版本将源码编译为菜单产物，身份包含源码与工具链信息。

Harness 的读取、逐文件写入／删除、检查和提交工具保留。候选文件按顺序原子保存，同一请求恢复未完成源码；更改上下文后拒绝旧候选。恢复后的源码必须重新检查。检查通过只代表编译通过，不代表浏览器验收。

Server 的项目保存接口接收源码并重新编译，不信任客户端上传的产物；随后使用现有项目权限和版本比较保存。Build 固定自定义外观和菜单产物，正式播放器不在玩家浏览器中重新编译。

## 7 窗口与执行隔离

左侧真实播放器运行在可信预览 iframe 内，地图、弹窗、焦点、快捷键和 CSS 尺寸响应只作用于游戏窗口。右侧是官方 Harness GUI；两个窗口的界面行为独立。

生成菜单使用另一个 opaque-origin iframe：它不能读取平台 DOM、Cookie 或存储。宿主检查确切窗口、origin 和一次性凭证后传递 MessagePort，校验命令身份、已知动作、消息数量和会话生命周期；卸载后撤销权限。

菜单 CSP 阻止网络请求、远程脚本、媒体、子 frame、表单和 worker，只开放已声明的脚本、样式与封面资源。iframe 和 CSP 属于浏览器边界，不能代替后续生产执行环境的资源配额与进程隔离。

## 8 官方对话托管边界

Studio 通过 `POST /aurora/game-agent/projects/:projectId/appearance/web` 打开、轮询或关闭会话。Nest 沿用 FD 登录，检查现有影游项目的 `story.generate`、`story.edit` 权限和可信 Studio origin，再补入真实用户、项目身份和项目标题。浏览器不决定工作区归属。旧 `/api/dev/appearance-harness` 路由已删除，不再另留仅本地可用的对话入口。

官方 GUI 挂载在 `/aurora/game-agent/projects/:projectId/appearance/web/:id/`，HTTP 资源、RPC 和 WebSocket mux 统一进入 Nest。每次 HTTP 请求和 WebSocket 建连均重新检查账号及项目权限；Worker 再核对已准入会话的用户、项目和会话身份。Worker 的 `/v1/game-agent/appearance/web` 控制接口以及对应 `/:id/proxy/*` 代理只面向可信内网，要求独立内部令牌和 Server 产生的作用域信息。官方子进程的端口、启动令牌、鉴权 Cookie 和模型密钥均留在服务端。

代理先私下初始化确切工作区与固定官方会话，再交付首个 GUI 页面，防止官方默认导航创建另一份会话。浏览器仅能使用固定会话的必要 HTTP/RPC/只读流与文字对话；宿主文件、任意工作区、其他会话、设置、模型切换、终端和上传接口不开放。请求、响应、流数量和并发均有上限。仍使用官方对话组件与扩展点，不增加另一套聊天渲染器或 Agent 循环。

Nest 开启 `GAME_AGENT_ENABLED=true` 时必须配置 `GAME_AGENT_WORKER_URL`、`GAME_AGENT_INTERNAL_TOKEN` 和 `GAME_AGENT_STUDIO_ORIGIN`。后者是完整且唯一的 Studio origin，生产为 HTTPS，本地可用 HTTP loopback；不带路径和尾斜杠。Worker 必须配置绝对私有目录 `GAME_AGENT_WORKSPACE_ROOT`，启动时实际验证原子写入和同步。生产入口将 `/aurora/game-agent/*` 的 HTTP 与 WebSocket 升级直接送入 Nest，并按现有约定去掉 `/aurora`。本地 Studio 沿用原生 `/aurora/:path*` Next rewrite，设置 `AURORA_PROXY_TARGET` 指向本地 Server；Nest 路由无此前缀时设置 `AURORA_STRIP_PREFIX=1`。不增加另一套开发入口或 Web rewrite。新加坡生产入口已配置这条路由；每次相关发布仍需验证 HTTP/WebSocket 和项目权限。

持久工作区按用户、现有影游项目、浏览器窗口键和 locale 计算不透明目录名，保存稳定 public session UUID、官方 session ID、最后请求上下文、未完成候选和官方历史。元数据与上下文采用受大小限制的原子写入；损坏或版本不符时明确失败，保留原文件；拒绝符号链接及路径逃逸。同内容重连保留请求身份，改变源码或上下文仍拒绝旧候选；恢复候选后必须重新检查。编辑窗口的 admission lease 阻止过期关闭请求结束新 admission。

正常离开和优雅重启先停止官方子进程组、撤销 HTTP/WebSocket，再释放文件系统 lease，保留工作区文件。部署契约为单 Worker、副本数 1、私有持久 ReadWriteOnce 卷和 Recreate 更新。生产已启用独立组件：卷挂载 `/var/lib/game-agent/workspaces`，UID/GID 1001 在其中创建私有 `sessions` 目录，Pod 使用 fsGroup 1001；只读镜像之外仅开放持久卷和受大小限制的 `/tmp`。PVC 使用保留标记，停用组件不自动删除工作区；手动删除 PVC 仍受底层回收策略影响。模型密钥仅进入 Worker，内部令牌通过另一份 Secret 的单个键注入 Worker 与 Nest，不投射整份业务密钥。当前每个 Worker 最多同时运行两个对话进程，不提供多副本会话路由或分布式文件写入。

`.com` 的六个应用服务运行在账号 `5332868355276356`、`ap-southeast-1` 的
`fizzdragon-com-sg` 集群和 `fizzdragon` 命名空间。日常发布从干净 `main` 的固定 HEAD
构建镜像，更新选定组件并保留现网配置与工作区；Server、Studio 与 Worker 的相关修改
应在同一发布中审核。不要把切流前暂停／隔离配置重新应用到生产。具体流程见
[新加坡发布说明](../../deploy/aliyun-sg/README.md)。

强制崩溃不承诺无条件自动恢复。Worker 在 spawn 前保存启动标记，并立即记录子进程的 Linux PID、启动时刻、boot ID 和 PID namespace。只有同一 boot/namespace 中旧父进程及已登记子进程均能证实消失时才允许自动接管；仍存活、PID 复用、缺失子进程记录、跨 namespace 或证据不足均拒绝接管。遇到这种拒绝，运维必须先证明旧 Pod/进程组已经停止、旧卷挂载已释放，才清理该工作区过期的 `.lease`；不得因时间已久而解锁，不删除源码、候选、元数据或历史。

Server 仍是项目写入权威；模型执行器只产生经过检查的预览提案。文件系统持久化和
进程恢复契约见 [Game Agent 说明](../../apps/game-agent/README.md)。

## 9 验收与能力限制

本地账号／权限 fixtures、HTTP/WebSocket 假服务、文件系统和独立进程测试验证相应
边界；它们不能替代真实账号、模型、生产网络和卷的验收。macOS 测试不能计为 Linux
进程身份及强制崩溃恢复分支已验证。

已有私有环境检查使用真实 FD 账号和百炼模型，覆盖拥有的项目、模型对话、工具外观
修改、项目保存／重载，以及优雅 ACK Worker 重启后恢复同一会话与历史。恢复曾需要
点击 Reconnect；这不建立自动重连或强制崩溃恢复的保证。

上线检查覆盖公开 HTTPS、就绪、数据源绑定和未登录访问边界。一次新的公开域名
真实登录 → 对话修改 → 保存 → 返回恢复 → Build / 发布完整旅程，及移动设备、支付与
全部素材类型的验收，仍须按实际执行范围分别报告，不能由容器就绪或上述局部检查推断。

日常回归应覆盖项目进入与返回、原生／自定义菜单开始、真实地图与焦点、返回菜单后
继续、主题和多语言文案、源码检查／保存、失败候选恢复，以及桌面与手机窗口。

当前完整地图数据、任意游玩／选项界面源码、受控数值读写和通用项目素材 API 尚未
提供。后续需求在同一影游运行时和 SDK 中扩展，先固定状态归属、权限和失败行为，
再通过真实项目试玩及正式 Build 验证；不建立脱离影游项目的平行运行路径。
