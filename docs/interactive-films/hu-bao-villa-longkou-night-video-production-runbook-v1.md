# 《虎豹别墅：龙口入夜》21 段双模型视频手工生产执行手册 v1.2

> 状态：可执行生产手册  
> 适用场景：暂不依赖 Story Studio 内置生成，由创作者使用 HappyHorse 1.1 + Wan 2.7 生成并规范归档  
> 最终交付：21 个已验收的 15 秒无声视频母版，而不是 21 次生成请求  
> 上游准源：[故事策划圣经 v1.2](./hu-bao-villa-longkou-night-story-bible-v1.md) 与 [双模型导演级提示词包 v1.6](./hu-bao-villa-longkou-night-video-prompt-pack-v1.md)

本文不改写故事，也不重复 21 条完整提示词。它只解决一个问题：创作者打开视频生成平台后，应按什么顺序准备参考素材、选择 HappyHorse 或 Wan、提交每条任务、判断是否重做，以及怎样保存文件，确保以后能够一对一回填 Story Studio。

### 创作者唯一执行入口

如果参考图片已经生成完成，不需要再从故事圣经或参考图指南重新阅读。直接按以下顺序执行：

1. 先阅读本文第 1–5 节，确认模型、输入模式、目录和生产顺序。
2. 从第 6 节总表选择当前片段；第一条固定为 `hbln-s00-dragon-returns`。
3. 点击总表对应的 `clipId`，到[双模型导演级提示词包 §4](./hu-bao-villa-longkou-night-video-prompt-pack-v1.md)复制该片段的完整提示词。
4. 每生成一个候选，立即按本文第 7 节验收；通过后才进入下一条有依赖关系的片段。

不要把 21 条提示词一次性全部提交。HappyHorse 1.1 只负责总表明确标注的 8 条；其余 13 条必须使用 Wan 2.7 首尾帧模式。

## 1. 先看结论

- 最终必须得到 **21 个视频母版**，每个 15 秒；任意一条游戏路径播放其中 8 个，总时长 120 秒。
- 21 个母版分布为：S00 1 个、S01 2 个、S02 2 个、S03 2 个、S04 3 个、S05 3 个、S06 4 个、结局 4 个。
- 视频生成使用 **16 个正式逻辑输入槽**：8 个源参考族、5 个 Join Frame、S00 的首尾帧、E04 的黑场前尾帧。实际归档为 23 个参考相关文件，明细见参考图生产指南。
- 模型固定为：HappyHorse 1.1 R2V 4 段、HappyHorse 1.1 I2V 4 段、Wan 2.7 首尾帧 13 段。
- 当前 Story Studio 还没有“上传已完成视频并直接设为镜头采用版本”的完整入口。现阶段先在外部生成并按本文归档；上传功能完成后，21 个母版按 `clipId` 一对一挂回镜头。
- 不要一次性盲生成 21 条。先通过 S00，再打通 8 段真结局路径，确认视觉语法和合流帧可靠后，再补齐剩余 13 段。
- 角色、场景、道具和锁定帧的逐张生成说明见：[《参考图生产指南 v1.0》](./hu-bao-villa-longkou-night-reference-image-guide-v1.md)。先按该指南完成第一批 5 张参考板，再开始 S00。

### 1.1 模型能力依据（2026-07-13 核对）

- HappyHorse 1.1 官方提供 R2V（1–9 张参考图）与 I2V（单首帧），支持 1080P、16:9、3–15 秒；API 提交时必须显式设置 `watermark=false`：[HappyHorse R2V API](https://www.alibabacloud.com/help/tc/model-studio/happyhorse-reference-to-video-api-reference)。
- HappyHorse 1.1 没有官方首尾帧模式；阿里云模型选型文档明确把首尾帧拼接分配给 Wan 2.7 I2V：[视频生成与编辑模型说明](https://www.alibabacloud.com/help/en/model-studio/video-generate-edit-model)。
- Wan 2.7 I2V 支持首帧 + 尾帧、2–15 秒和 1080P；正向提示词最多 5000 字符、独立负向提示词最多 500 字符。输出比例继承首帧，不提供单独的比例参数：[Wan 2.7 I2V API](https://www.alibabacloud.com/help/en/model-studio/image-to-video-general-api-reference)。
- 因此本项目采用固定双模型分工，不允许在生产时临时把 13 个首尾帧任务切回 HappyHorse。

提交前还必须确认模型、API Key 与 endpoint 属于同一区域；跨区域组合会直接失败。本文不锁死区域，但同一批 21 条任务应使用同一个可用区域和同一模型版本。

锁定模型 ID：

- R2V：`happyhorse-1.1-r2v`
- 单首帧 I2V：`happyhorse-1.1-i2v`
- 首尾帧：`wan2.7-i2v-2026-04-25`

## 2. 三条不可违反的生产规则

### 2.1 模型模式互斥

每个任务只能使用下列一种模式：

- **HappyHorse 1.1 R2V**：上传任务声明的 1–9 张人物、场景、道具参考；不得再上传首帧或尾帧。
- **HappyHorse 1.1 I2V**：只上传一张锁定首帧；不得额外加入人物、场景、道具参考图或尾帧。
- **Wan 2.7 First + Last Frame**：只上传锁定首帧和锁定尾帧；不得额外加入参考图。

如果平台界面的名称不同，以能力含义为准。不能为了“加强一致性”把三种输入混在同一次任务里。HappyHorse 目前没有首尾帧输入，因此 13 个合流任务不得改用 HappyHorse R2V 冒充尾帧控制。

### 2.2 所有视频最终只保留无声画面母版

- 提示词不要求模型创作最终对白、音乐、锣声或环境声；模型附带的原生音轨一律不采用。
- 画面内人物只在提示词规定的时间窗口做自然口型。
- 广播、录音和画外音出现时，画面内人物必须闭口。
- 字幕、选择按钮、结局题签、展览文字均不烘焙进视频。
- 声音、字幕和交互 UI 在画面验收后另行制作。

### 2.3 合流只认锁定 Join Frame

S01–S05 的同层变体必须从同一首帧出发并抵达同一张锁定尾帧。不得用某个上游视频临时截出的不同末帧替代 Join Frame，否则 21 段无法稳定拼成 64 条路径。

## 4. 双模型单条任务怎么提交

每一个视频都严格执行下面 14 步：

1. 在第 6 节总表中找到本次 `clipId`、生成模式和输入素材。
2. 打开 [双模型导演级提示词包 §4](./hu-bao-villa-longkou-night-video-prompt-pack-v1.md)，定位完全相同的编号和 `clipId`。
3. 按第 6 节选择指定模型与模式；上传且只上传该任务“模型输入”声明的图片。
4. HappyHorse 设置为 15 秒、16:9、1080P、`watermark=false`；R2V 按 `[Image 1]` 顺序上传，I2V 只上传首帧。HappyHorse 原生输出为 24 fps。
5. Wan 2.7 设置为 15 秒、1080P、`prompt_extend=false`、`watermark=false`；首帧绑定 `[Start Frame]`，尾帧绑定 `[End Frame]`。首尾帧本身必须是同一套 1920×1080、16:9 构图；不要向 Wan API 发送不存在的 `ratio` 参数。Wan 原生输出为 30 fps。
6. 两种模型生成的音轨都不进入母版。画面通过后统一移除音轨；Wan 输出再转为 24 fps CFR，保持 15 秒、首帧和尾帧构图不变。
7. 正向提示词按以下规则生成，不能把整份导演稿无脑粘贴：
   - 如果镜头提供 `Submission prompt`，只提交该代码块；它已包含全局风格与逐秒动作，不再拼接 §2.1。
   - 其他镜头按 `§2.1 全局正向前缀 → Positive prompt → Shot timeline` 拼接。
   - `Emotional arc`、`End-state contract`、验收重点和补充轨是导演与验收合同，不提交给模型。
   - 提交前统计最终正向提示词字符数；HappyHorse 与 Wan 均不得超过 4800 字符，给平台封装保留余量。禁止依赖平台自动截断。
8. 负向提示词按以下顺序拼接：
   - 提示词包 §2.2“全局硬负面约束”；
   - 该镜头的“专属负面”。
   - Wan 的独立负向提示词不得超过 500 字符；优先保留身份漂移、畸形手、文字水印、错误场景和镜头切换五类硬禁区。
9. 如果界面有独立负向框，则分开放入；如果只有一个提示词框，把精简后的负向约束放在最后，并确认整个输入仍未超过该模型上限。
10. 提交前截图保存模型、模式、时长、参数、参考图顺序和完整提示词，放入 `02-prompt-snapshots/<clipId>/`。
11. 首次只生成一个候选片段。下载原始文件，不在平台预览页上直接决定是否通过。
12. 按第 7 节逐帧验收；任何硬性项失败，标记拒收原因后重做。
13. 通过的候选先保留为原生候选，再制作统一 24 fps、无音轨的母版并复制到 `04-video-masters/`，不覆盖候选原文件。
14. 为母版写一份同名元数据 JSON 并计算 SHA-256；然后才开始下一条依赖该帧的任务。

时间紧时可以先完成并审核 21 个原生候选，统一转制在 21 段画面锁定后一次批处理；但原生候选和交付母版必须分目录保存。

> 提示词包中的 `[Image 1]`、`[Start Frame]`、`[End Frame]` 必须与实际上传顺序一致。不能只靠文件名猜测。

## 5. 推荐生产顺序

### 阶段 A：先证明视觉体系

1. 完成 REF-01–08。
2. 只生成 `hbln-s00-dragon-returns`。
3. S00 不通过就继续修正参考图或提示词，不进入其他 20 段。
4. S00 通过后提取 S00-FIRST、S00-LAST，并制作 E04-PREBLACK-END。
5. 完成并审核 JF-01–05。

此阶段完成标志：入口、龙口、陈澄、Maya、卡带机的视觉语言已稳定；8 个源参考、5 个 Join Frame、3 个首尾帧全部有固定文件和哈希。

### 阶段 B：先打通一条 120 秒真结局路径

按下列顺序生成：

```text
S00
→ S01B
→ S02B
→ S03B
→ S04B
→ S05A
→ S06A
→ E01
```

这 8 段全部通过后，先把它们按顺序无缝播放一遍。此时暂不加选择 UI，但必须验证：相邻镜头没有脸、服装、湿度、手伤、卡带/DV 状态或空间轴线跳变。

### 阶段 C：补齐中段变体

按层生成，完成一层再进入下一层：

```text
S01A
S02A
S03A
S04A、S04C
S05B、S05C
```

每条都必须与同层已通过片段抵达相同 Join Frame。不要因为单条画面“更好看”而接受不同末帧。

### 阶段 D：补齐其余即时结局

```text
S06B
S06C
S06D
```

三条都从同一 JF-05 开始。重点检查不同结果是由动作和人物关系产生，而不是角色、场景或道具随机变化。

### 阶段 E：最后补齐其余结局

```text
E02
E03
E04
```

E04 必须最后做，因为它依赖已批准 S00 的首帧，并要像素级呼应开场机位。

## 7. 每条视频的验收方法

### 7.1 技术硬门槛

以下任意一项失败，直接拒收：

- 时长不是 15 秒，画幅不是 16:9，或存在水印。
- 出现模型生成字幕、菜单、Logo、片名、伪界面文字。
- 人物换脸、年龄漂移、发型或服装漂移。
- 多手、多指、融合手、穿模、道具瞬移或违反重力。
- 生成了可听对白、音乐或不可分离的声音。
- 关键脸、手、卡带、卡带机或 DV 落出安全画面。
- 出现赛博霓虹、魔法粒子、血肉龙、血腥、现代游乐园人群。
- Frame 任务没有从锁定首帧准确开始，或 First + Last 任务没有抵达锁定尾帧。
- S00–S05 最后 2 秒仍有新口型、新手势、新灯光事件或新视线目标。
- S06A–D 最后 2 秒不稳定，无法覆盖“继续进入结局”按钮。

### 7.2 四遍审片法

1. **正常速度看叙事**：不看提示词，确认 5 秒内能看懂玩家上一选择造成了什么反馈。
2. **静音看表演**：确认眼神先于头部、表演克制、人物没有无理由尖叫或大幅后退。
3. **逐帧看物理**：重点检查脸、手、按钮、线缆、卡带、DV、水和玻璃反射。
4. **首尾对照**：将第 0 帧、锁定输入帧、13–15 秒稳定区和锁定输出帧并排比较。

## 8. 文件命名与元数据

### 8.1 候选与母版命名

候选文件：

```text
<clipId>__candidate-001__raw.mp4
<clipId>__candidate-002__raw.mp4
```

最终采用母版：

```text
<clipId>__master-v001__15s__1080p24.mp4
```

示例：

```text
hbln-s03b-save-tape__candidate-003__raw.mp4
hbln-s03b-save-tape__master-v001__15s__1080p24.mp4
```

不要把候选文件重命名为母版后覆盖原文件。母版是一次明确的“采用决定”，不是最新下载文件。

### 8.2 同名元数据 JSON

每个母版旁放一个同名 `.json`：

```json
{
  "project": "hu-bao-villa-longkou-night",
  "clipId": "hbln-s03b-save-tape",
  "promptPackVersion": "1.5",
  "generationMode": "first_last_frame",
  "model": "wan2.7-i2v",
  "durationSec": 15,
  "width": 1920,
  "height": 1080,
  "sourceFps": 30,
  "masterFps": 24,
  "audio": false,
  "candidateNumber": 3,
  "inputs": [
    { "slotId": "JF-02", "file": "jf-02-s02-to-s03.png", "sha256": "待填写" },
    { "slotId": "JF-03", "file": "jf-03-s03-to-s04.png", "sha256": "待填写" }
  ],
  "reviewStatus": "approved",
  "reviewedAt": "YYYY-MM-DDTHH:mm:ssZ",
  "masterSha256": "待填写"

```

### 8.3 SHA-256 记录

macOS 可在终端执行：

```bash
shasum -a 256 hbln-s03b-save-tape__master-v001__15s__1080p24.mp4
```

把结果写入同名 JSON 和 `06-checksums/masters.sha256`。参考图也执行相同操作。后续上传 Story Studio 时，以哈希确认没有选错版本。

## 10. 时间紧时的正确止损点

如果时间不足，不要交付 21 个未经审核的一次生成结果。按下列层级停下来，后续仍可继续：

1. **视觉样片完成**：S00 通过；16 个逻辑输入槽及其 23 个参考相关文件完整。
2. **可验证路径完成**：阶段 B 的 8 个母版通过，可以连续播放完整真结局路径。
3. **完整影游画面完成**：21 个母版全部通过，并完成四条结局直达路径串播。

每完成一个层级都归档提示词快照、候选、母版、元数据和哈希。不要跳过阶段 B 直接批量补齐 21 条，否则错误的脸、道具或 Join Frame 会放大为整批返工。

## 11. 交付完成定义

只有同时满足以下条件，才叫“21 段视频生成完成”：

1. `04-video-masters/` 中恰好有 21 个唯一 `clipId` 的母版视频。
2. 每条母版均为 15 秒、16:9、1080p、24 fps CFR、H.264、无水印、无音轨、无烘焙字幕；原生候选保留模型原始帧率供审计。
3. 每条都有提示词快照、输入参考版本、验收记录、同名 JSON 和 SHA-256。
4. 16 个逻辑参考输入槽及其 23 个参考相关文件都有固定版本和 SHA-256。
5. 真结局 8 段路径完整串播通过。
